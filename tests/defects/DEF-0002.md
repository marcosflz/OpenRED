## Resumen

`PropellantRegresionLSM.__init__` construye el vector de tiempos como
`np.arange(0, int(maxIters*dt) + dt, dt)`, que **no cubre** la simulación completa en dos casos:

1. `int(maxIters*dt) < 1` (p. ej. `It=300, dt=0.001`): el `arange` queda en `[0.0]` y
   la primera línea de consola indexa `time[1]` → `IndexError`.
2. `maxIters > len(time) + 1` (p. ej. `It=300, dt=0.005`: `int(1.5)+0.005 = 1.005` →
   201 muestras): la consola indexa `time[201]` en la iteración 202 → `IndexError`.

En la app original el fallo ocurre dentro del hilo de cálculo
(`front_propDes.run_simulation`), por lo que la consola queda a medias y el error se
imprime en `stderr` sin diálogo.

## Reproducción

```bash
engine/.venv/Scripts/python.exe - <<'PY'
# (requiere el arnés temporal de gen_fixtures; el generador ya documenta el caso)
# It=300, dt=0.005, dh=0.0001 y el grano Tubular de tab_1
PY
```

Resultado observado:

```
IndexError: index 201 is out of bounds for axis 0 with size 201  (back_1.py:229)
```

Resultado esperado: o bien un vector de tiempos que cubra `It` iteraciones, o un error de
dominio con mensaje (código 1006/-32602), nunca un `IndexError`.

## Causa raíz

`legacy/back_modules/back_1.py:59`:

```python
self.time = np.round(np.arange(0, int(self.maxIters * self.dt) + self.dt, dt), self.workingPrecision)
```

La suma de `dt` pretende incluir el extremo, pero el `int()` trunca el producto antes de
sumar; según el redondeo binario del producto, `int(It·dt) + dt` puede quedar por debajo de
`It·dt` (caso 1) o muy por debajo de `It` iteraciones (caso 2). El bucle de `run()` asume que
`time` tiene al menos `maxIters` entradas.

## Impacto

- El clon debe decidir el comportamiento para estas combinaciones: la opción adoptada
  (paridad estricta) es **replicar la fórmula** y devolver error de dominio `-32602`
  cuando `It > len(time)`, en lugar de un `IndexError`.
- Los fixtures smoke usan `It=300, dt=0.01` (`int(3)+0.01 = 3.01` → 301 muestras) para
  evitar el defecto y mantener el CI rápido; `engine_knsu.json` (full) usa los valores reales
  de `tab_1` (`It=10000, dt=0.005`) donde la simulación termina por masa antes del desborde.

## Corrección propuesta

- Clon (`engine/openred_engine/modules/back_1.py` + `services/engine.py`): conservar la
  fórmula exacta (paridad numérica), validar `It <= len(time) + 1` y responder `-32602`
  con mensaje explicativo si no se cumple.
- Fixtures: mantener la reducción smoke documentada en `reduction` y en el README.
