## Resumen

Ejecutar `back_1` con los parámetros de `workingDirectory/config.json` (`tab_1`) **no**
reproduce `workingDirectory/Engines/KNSU-32-RT65.json`: el JSON guardado se generó con
`cx_real = 0.0` mientras que `config.json` guarda `"Tubular-Grain_cx_real": "0.005"`.
El resto de entradas coincide (P0, Rt, R2, Lc, dt, dh, It, a, n, R, T1, cChar, rho_b,
P1_min, P1_max, cy_real, r_in).

## Reproducción

```bash
uv run python tools/parity/gen_fixtures.py --only t1 --full
```

Resultado observado (fixture fresco, `ItMax=10000, dh=0.0001`):

```
585 iteraciones, t_final = 2.925 s, maxPressure = 1.469e6 Pa
```

Referencia almacenada (`inputs/KNSU-32-RT65.json`):

```
375 iteraciones, t_final = 1.875 s, maxPressure = 1.618e6 Pa
```

Con `cx_real = 0.0` (como la referencia) la simulación converge a 375 iteraciones y a
`maxPressure ≈ 1.618e6 Pa`, confirmando que la diferencia es la posición del agujero del
grano, no un cambio de código.

## Causa raíz

`config.json` fue autoguardado más tarde que el motor de referencia (el usuario desplazó el
agujero a `cx_real=0.005`); el `KNSU-32-RT65.json` del repo quedó obsoleto respecto a esa
configuración.

## Impacto

- **T1-6/T1-8**: la comparación byte a byte del export debe hacerse contra el fixture fresco
  (`engine_knsu.json`), no contra el JSON del repo legacy.
- **T2/T3** (retención): `inputs/KNSU-32-RT65.json` sigue siendo el motor que consumen
  `nozzle`/`cad` (sus `results.tree_data`, `CADx/CADy/CAD0`, `totalMass` son válidos como
  entrada); su `meanPressure` (790190.5221096972) coincide con la P1 de diseño de `tab_2`.
- A1 no debe "arreglar" el motor para reproducir el fichero obsoleto.

## Corrección propuesta

Ninguna en el motor. Documentar en `contracts/fixtures/README.md` (hecho) y mantener ambos:
`engine_knsu.json` como referencia T1 actual y `inputs/KNSU-32-RT65.json` como entrada T2/T3.
