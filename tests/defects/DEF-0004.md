# DEF-0004 — `nozzle.op_point` construye la tobera con `p1t` en vez de la P1 de diseño

| Campo | Valor |
|---|---|
| **ID** | DEF-0004 |
| **Severidad** | alto (rompía la paridad de T2-6/T2-7: régimen y empuje off-design) |
| **Estado** | corregido (A1) |
| **Componente** | engine `services/nozzle.py::op_point` |
| **Detectado en** | `c2250d0` · `A0/A10` · 2026-09-25 (parity run) |

## Resumen

La clasificación de régimen y el empuje de los 8 puntos de barrido no coincidían con el
legacy. En `front_nozDes.updateMapPlots`, `opPoint_plot` se invoca sobre
`self.calculatedNozzle`, la tobera construida en `calculate_n_show` con la **P1 de diseño**
(la del entry, por defecto la presión media del motor). La implementación inicial creaba una
tobera nueva con `P1 = p1t` (la presión del punto de operación), lo que cambia
`self.M2`, el área de salida, `PR_crit`, `PRatio_*` y las curvas: el resultado ya no es el
off-design del legacy. **Corregido**: `op_point` acepta `p1`/`p1Design` y construye la
tobera con la P1 de diseño; `run_parity.py --only t2` da 8/8 puntos en verde.

## Reproducción

```bash
uv run python tools/parity/run_parity.py --only t2
```

Primer punto del barrido (`P1t = min(P) + 0.05·(max(P) − min(P)) = 175904.02 Pa`,
`P0 = 100000 Pa`, diseño `P1 = 790190.5221096972 Pa`):

|---|---|---|
| `F` (kg) | 1.7860 | 1.5834 |
| `Pe` (Pa) | 135129.1155 | 100000.0 |
| `ratios.Pe_P1t` | 0.7682 | 0.5685 |
| `ratios.Pe_P0` | 1.3513 | 1.0 |
| `regime` | `Normal Shock Inside` | `Under-Expanded` |

(`tools/parity/run_parity.py` reporta los 8 puntos; el fixture contiene `result` canónico
formateado y `raw` con los dobles.)

## Causa raíz

`engine/openred_engine/services/nozzle.py::op_point`:

```python
nozzle = nozzle_cls(def_check, p1t, n, dt, engine, spec)   # <- P1 = p1t
output = nozzle.opPoint_plot(p1t, p0)
```

En `TOPBN.BellNozzle.__init__`, `P1` define `self.M2`, `self.e`, `self.R2`, `self.F`,
`self.PR_crit`, `self.M_x_Sup`, `self.geo_Nozzle`, etc. (`legacy/back_modules/NozzleLibrary/TOPBN.py:75-123`).
`opPoint_plot` sólo recibe `(P_Off, P0)` y reutiliza ese diseño.

## Impacto

- T2-7 (sliders off-design en vivo): mapa de presión/Mach, 4 ratios y etiqueta de régimen
  incorrectos en todas las posiciones.
- T2-6: el barrido de 8 puntos falla en `F`, `Pe`, ratios y régimen.
- La UI mostraría regímenes/empujes que no corresponden al motor cargado.

## Corrección propuesta

1. Aceptar `p1` opcional en `nozzle.op_point` (el fixture ya lo envía:
   `params_base.p1 = 790190.5221096972`) y, si falta, usar
   `engine["results"]["meanPressure"]` como P1 de diseño (es el valor por defecto del
   switch "P1 - Mean Value").
2. Construir la tobera con esa P1 de diseño y llamar `opPoint_plot(p1t, p0)`.
3. Mantener `PR = Pe/P1t` y `ratios` con los ratios formateados a 4 decimales
   (`front_nozDes.updateMapPlots`).
4. Esquema actualizado: `contracts/schemas/nozzle.schema.json` (`p1` opcional documentado).
